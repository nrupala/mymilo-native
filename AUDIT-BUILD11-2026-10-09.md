# Build 11 (v0.6.0) — Self-Audit, 2026-10-09

Wright's own navigation audit of the app, per Nrupal's directive
("you see the build… find all visual defects and operability
defects just by navigating in the app"). Method: full source read
of every UI file (MainActivity 602 lines, Theme, MainViewModel,
Daos, voice session) checked against the defect classes from
builds 1–11 and the simplicity doctrine. No Android emulator
exists on the VM or the Aetheris box (no KVM either side), so this
pass is source-level; the durable pixel-level capability is a CI
screenshot job (Robolectric on the runner), wired in with
build 12 so future audits include literal screenshots.

## Verified sound (checked, no defect)

- Skin color pairs: all four skins define matching on-colors;
  no dark-on-dark pairing found (build-1 trap does not recur).
- Session titles are meaningful: first 60 chars of the first
  user message.
- Drawer scroll fix (build 11) correctly bounds the thread list.
- DAO already has session/message delete queries — thread
  management is missing only its ViewModel + UI wiring.

## P1 — operability defects (fix in build 12)

1. **No thread delete or rename.** Session rows are plain
   tappable text. (Owner-reported 2026-10-09; code-confirmed.)
2. **"Disconnect device" is one-tap destructive.** `disconnect()`
   clears the token immediately — no confirmation. One stray tap
   = the full re-setup dance. Needs the two-step confirm.
3. **Setup screen cannot scroll** and has no IME padding: on a
   small screen or with the keyboard open, the Connect button —
   the only action that matters on first run — can be pushed out
   of reach.
4. **No waiting presence in the conversation.** While the server
   thinks (Phi answers can take a minute or more), the only
   feedback is a 12sp gray status line under the composer. No
   in-list "Milo is thinking" row, no stop control. Reads as a
   hang — the same silence class as the assistant-session defect.
5. **Replies are not selectable; there is no copy.** Plain `Text`
   in `MessageBubble`, no `SelectionContainer`, no message
   actions at all. (Also the owner's Muse/Town parity ask.)

## P2 — clarity defects (build 12 drawer/surface redesign)

6. **Active thread is not highlighted** in the drawer list —
   every row looks identical.
7. **New chat opens to a blank void.** No greeting, no example
   prompts, no capability hints. A first-time, non-technical
   user gets an empty screen and a text box.
8. **The drawer is an engineering surface**: unlabeled emoji
   toggles (🔊/🔇 in the top bar), "Skin" rendered as ●/○ text
   circles, unexplained buttons (Sync now), and a version line
   reading "MyMilo v0.6.0 · build 11" — jargon on the surface,
   against the simplicity doctrine.
9. **Hardcoded `Color.Gray` texts** (skill count, setup help,
   status line) ignore the skin; washed out on the light
   Daylight skin.
10. **Top bar carries no state**: only "mymilo" — no current
    thread title, no at-a-glance offline/queued indicator.

## P3 — polish

11. Update dialog truncates release notes mid-word (240 chars).
12. Setup screen shows the device token in clear text while
    typing, and the server URL is freely editable — one typo
    produces an opaque failure. (Sign-in pairing retires both.)
13. Message bubbles size to content width; long assistant
    answers read better as full-width text (the Perplexity
    pattern — adopted as the build-12 reference).
14. Composer buttons are bare glyphs (🎤 / ➤) with
    content-sized touch targets.

## Fix train

All P1 + the parity features (sources row, thread share/export,
long-press message actions) + thread management + Perplexity-style
surface land as **build 12**, with server **v0.40.0** supplying
the sources data. P2 items fold into the same build's drawer
redesign. P3 items 11–14 ride along; item 12 closes with
sign-in pairing (server v0.39.0 follow-on + app).

## Second pass (end-user walk of the remaining surfaces, same day)

Owner's follow-up directive: "as an enduser of the app find other
defects and roll them solved in the next build."

15. **Assistant panel: long replies push the buttons away.** The
    session Column never scrolls; a long answer (a market brief!)
    makes Open app / Done unreachable.
16. **Assistant panel is one-shot.** After an answer there is no
    way to ask a follow-up or retry by voice — only Open app or
    Done. (Multi-turn overlay stays its own build; build 12 adds
    an "Ask again" voice retry.)
17. **Assistant panel ignores the chosen skin** — hardcoded
    Midnight regardless of the user's setting.
18. **Voice answers vanish.** Nothing the assistant says is saved
    to any thread; open the app later and the conversation never
    happened.
19. **Assistant panel shows no sources** even though the server
    now sends them (v0.40.0).
20. **Share-to-MyMilo is declared but dead.** The manifest
    advertises ACTION_SEND (other apps can hand text to Milo),
    but the activity never reads the shared text — the user's
    content is silently swallowed.
21. **Raw recognizer fallback**: "Voice input error (7)" exposes
    an error code to the user.
22. **Recorded decision (not a defect):** `allowBackup` stays ON.
    It restores the device token on a new phone — the owner's
    "self-sufficient" requirement wins; the token remains
    revocable server-side if a device is lost.

Second-pass fixes 15–21 ride build 12 alongside the first pass.

## Found on device by the owner (2026-10-09, build 13)

23. **The in-app updater could never install anything.** The
    build-10 persistence fix moved update downloads from
    cacheDir to filesDir/updates — but `res/xml/file_paths.xml`
    still declared only the cache root, so
    `FileProvider.getUriForFile` threw "Failed to find configured
    root" for every downloaded APK and Install died with a
    cache-path error (owner's report: "cache error when
    downloaded build 13 and tried to install it"). The updater
    had never completed an end-to-end install on a device —
    every build until now arrived by sideload. Fixed in build 14
    (v0.7.1): files-path root added; `install()` now returns
    success/failure and the UI says so in plain words instead of
    crashing. Lesson recorded beside #12: when storage moves,
    the sharing permissions move with it — and an update path is
    only real once it has installed something.
